Real-Time Frame-Based Video Streaming System
 (Comprehensive Spec)
Objective
Build a low-latency, frame-addressable video streaming system with synchronized audio, seamless
looping, and binary command control. The system must support high concurrency, deterministic
playback, and modular downstream integration without coupling to rendering layers.
System Principles
- Frame-level control instead of file playback
- Continuous streaming (no resets or gaps)
- Deterministic and command-driven playback
- Low latency (<500ms)
- Horizontally scalable and stateless

Video Preprocessing
Input: Standard video formats (MP4, MOV). Output: frame sequences and aligned audio chunks.
{
  frames: [F1, F2, ..., Fn],
  audioChunks: [A1, A2, ...],
  fps: 30,
  duration: float
}
Requirements:
- Normalize FPS
- Assign frame indices


- Align timestamps
- Preload into memory/cache
Loopable Streaming Engine
Ensures seamless playback without reset or buffering.
pointer = (pointer + 1) % totalFrames
Enhancements: pre-decoding, optional crossfade
Audio Synchronization
Maintain continuous playback with tight sync.
frame.timestamp == audio.timestamp
Drift handled via frame skipping or audio drop (never pause).
STCP Binary Command System
All control must be binary-based.
PLAY
PAUSE
RESUME
SEEK
SET_SPEED
SWITCH_SOURCE
SET_LOOP_MODE
SYNC
Binary Payload
{
  action: uint8,
  streamId: uint8,
  frameIndex: uint32,
  timestamp: float,
  speed: float
}
Streaming Layer (Mediasoup)
- RTP-based streaming
- Separate audio/video tracks
- Single producer, multiple consumers
- Replace frame source dynamically


Multi-Stream Switching
- Instant switching (<100ms)
- No renegotiation
- Same transport pipeline
Core Scheduler
